# יומן כושר 🏋️ — אפליקציית אימונים ומשקל (PWA)

React 18 + Vite + Tailwind CSS · עברית מלאה (RTL) · Dark Mode · מותאמת למובייל · עובדת גם בלי קליטה.

## הרצה מהירה

```bash
npm install
npm run dev          # פותח על http://localhost:5173 (וגם בכתובת ברשת המקומית — אפשר לפתוח מהטלפון)
npm run build        # בנייה לפרודקשן לתיקיית dist
npm run preview      # בדיקת הגרסה הבנויה (כולל ה-Service Worker)
```

לפני ההרצה הראשונה צריך להגדיר פרויקט Firebase ולמלא את הקובץ `.env` — ההוראות בסעיף "הגדרת Firebase" למטה.

## התקנה על הטלפון (PWA)

PWA דורש HTTPS. הדרך הקלה: להעלות ל-Vercel / Netlify (חינם):

1. דחוף את הפרויקט ל-GitHub → ב-Vercel: **Add New Project** → בחר את הריפו → Deploy
   (הקבצים `vercel.json` ו-`public/_redirects` כבר מטפלים בניתוב).
2. הוסף ב-Vercel את 6 משתני הסביבה של Firebase (ראה "הגדרת Firebase" למטה) ואת כתובת האתר ל-Authorized domains.
3. פתח את הכתובת בטלפון:
   - **אייפון (ספארי):** כפתור שיתוף ← "הוסף למסך הבית".
   - **אנדרואיד (כרום):** יופיע "התקן אפליקציה", או דרך מסך ההגדרות באפליקציה.

אחרי ההתקנה האפליקציה נפתחת במסך מלא, וכל הקבצים שלה (כולל הפונט) שמורים מראש — היא נטענת ועובדת גם במצב טיסה.
שינויים שעושים בלי קליטה נכנסים לתור ונשלחים לענן אוטומטית כשהחיבור חוזר.

## הגדרת Firebase (התחברות ושמירת נתונים)

האפליקציה דורשת התחברות: כל משתמש נרשם עם אימייל וסיסמה, והנתונים שלו נשמרים ב-Firestore תחת ה-UID שלו בלבד.

**1. יצירת פרויקט**
1. נכנסים ל-[console.firebase.google.com](https://console.firebase.google.com) ← **Create a project** (או "הוספת פרויקט").
2. נותנים שם (למשל `fitness-app`). את Google Analytics אפשר לכבות. ← **Create project**.

**2. הפעלת התחברות עם אימייל וסיסמה**
1. בתפריט הצד: **Build ← Authentication** ← **Get started**.
2. בלשונית **Sign-in method** בוחרים **Email/Password**.
3. מפעילים את המתג הראשון (**Email/Password**) ← **Save**. את "Email link (passwordless sign-in)" משאירים כבוי.
4. בלשונית **Settings ← Authorized domains** לוחצים **Add domain** ומוסיפים את כתובת האתר ב-Vercel (למשל `fitness-app-or.vercel.app`). `localhost` כבר מופיע שם.

**3. יצירת מסד הנתונים Firestore**
1. בתפריט הצד: **Build ← Firestore Database** ← **Create database**.
2. מיקום: `eur3 (europe-west)` או `me-west1 (Tel Aviv)`. **שימו לב: אי אפשר לשנות אחר כך.**
3. בוחרים **Start in production mode** ← **Create**.
4. בלשונית **Rules** מוחקים את מה שיש, מדביקים את כל התוכן של הקובץ `firestore.rules` מהפרויקט ← **Publish**.

**4. רישום אפליקציית Web וקבלת המפתחות**
1. לוחצים על ⚙️ ליד "Project Overview" ← **Project settings**.
2. למטה ב-**Your apps** לוחצים על האייקון `</>` (Web). נותנים כינוי ← **Register app** (בלי Firebase Hosting).
3. מופיע קוד עם `const firebaseConfig = { apiKey: ..., authDomain: ..., ... }`. מעתיקים כל ערך למשתנה המתאים:

| בקוד של Firebase | משתנה סביבה |
|---|---|
| `apiKey` | `VITE_FIREBASE_API_KEY` |
| `authDomain` | `VITE_FIREBASE_AUTH_DOMAIN` |
| `projectId` | `VITE_FIREBASE_PROJECT_ID` |
| `storageBucket` | `VITE_FIREBASE_STORAGE_BUCKET` |
| `messagingSenderId` | `VITE_FIREBASE_MESSAGING_SENDER_ID` |
| `appId` | `VITE_FIREBASE_APP_ID` |

- **במחשב:** מעתיקים את `.env.example` ל-`.env`, ממלאים, ומריצים מחדש `npm run dev`.
- **ב-Vercel:** Project ← **Settings ← Environment Variables** ← מוסיפים את 6 המשתנים ← **Deployments ← ⋯ ← Redeploy**
  (חובה Redeploy: הערכים נכנסים לקוד בזמן הבנייה).

> המפתחות האלה **לא סודיים** — הם מזהים את הפרויקט ומופיעים בכל אפליקציית Firebase בדפדפן.
> מה שמגן על הנתונים הוא חוקי האבטחה (`firestore.rules`): כל משתמש יכול לגשת רק ל-`users/{ה-UID שלו}`.

**5. בדיקה:** פותחים את האפליקציה ← "הרשמה" ← אחרי שמזינים שקילה, היא מופיעה ב-Firebase Console ←
Firestore ← `users` ← (ה-UID שלך) ← `weights`. ב-Authentication ← Users רואים את המשתמש.

**מה קורה בפועל**
- כל שינוי נשמר מיד בטלפון ונשלח ל-Firestore תוך שתי שניות. בלי קליטה הוא נשמר בתור ונשלח כשהחיבור חוזר.
- בהתנתקות כל הנתונים נמחקים מהמכשיר (נשארים בענן). משתמש אחר באותו טלפון לא רואה אותם.
- נתונים שנשמרו בטלפון בגרסה הקודמת (לפני שהיו חשבונות) עולים אוטומטית לחשבון בהתחברות הראשונה.
- תמונות שמעלים לתרגיל מוקטנות ונשמרות בתוך מסמך התרגיל, כך שלא צריך Firebase Storage (שדורש תוכנית בתשלום).
- הכל נכנס במסלול החינמי (Spark) לשימוש אישי.

## מעקב סוכר בדם

בלשונית **מדדים ← סוכר** (וגם בכרטיס בדף הבית) מזינים רמת סוכר ב-mg/dL ומסמנים מתי נמדד: בצום, לפני ארוחה, אחרי ארוחה, לפני שינה או אחר.
אפשר להזין כמה מדידות ביום ולערוך/למחוק כל מדידה.
מוצגים ממוצע יומי, שבועי וחודשי עם ההפרש מהתקופה הקודמת, מגמה (mg/dL לשבוע), גרף וטבלאות.
אפשר לסנן לפי "בצום" או "אחרי ארוחה", כי השוואה בין מדידות מאותו סוג אמינה יותר.
את הכרטיס בדף הבית אפשר להסתיר בהגדרות. המעקב נועד לתיעוד אישי ואינו מחליף מעקב רפואי.

## לחץ דם

בלשונית **מדדים ← לחץ דם** מזינים לחץ עליון, תחתון ודופק (לא חובה). יש ממוצעים יומיים, שבועיים וחודשיים, מגמה ב-mmHg לשבוע, גרף ורשימות, כמו בסוכר.

## דוח לרופא (PDF)

כפתור **"דוח לרופא"** בכל אחד ממסכי המדדים פותח דוח מסודר:
בוחרים תקופה (30 יום / 3 חודשים / חצי שנה / תאריכים חופשיים), אילו מדדים לכלול, ושם שיופיע בדוח.
בדוח: סיכום (התחלה, סוף, שינוי, ממוצע, טווח), גרף, טבלת ממוצעים שבועיים למשקל, סוכר לפי סוג מדידה ויומן מדידות יומי,
ולחץ דם עם כל המדידות. לוחצים **"הדפסה / PDF"** ובוחרים "שמור כ-PDF" (במחשב) או שיתוף ← הדפסה (בטלפון).
הדוח בנוי כדף אינטרנט להדפסה ולא בספריית PDF, כי ספריות PDF בדפדפן לא מציגות עברית כמו שצריך.

## משקל יעד

במסך המשקל לוחצים **"הגדר משקל יעד"**. האפליקציה מציגה כמה נשאר, פס התקדמות מנקודת ההתחלה,
והערכה מתי תגיע ליעד לפי קצב 30 הימים האחרונים. היעד נשמר בחשבון ומסונכרן בין מכשירים.

## גרף התקדמות לכל תרגיל

בכרטיס של כל תרגיל (מאגר התרגילים ← לחיצה על תרגיל) מופיע גרף לאורך כל האימונים:
**1RM משוער** (נוסחת Epley, כמה היית מרים לחזרה אחת לפי הסט הכי טוב), **משקל מקסימלי** או **נפח**.
בתרגילי משקל גוף מוצגות חזרות מקסימליות.

## תזכורות

- **בדף הבית:** הכרטיס "המדידות של היום" מסמן ✓ ליד כל מדד שכבר נמדד היום, ומציין מה עוד חסר.
- **התראות בטלפון:** בהגדרות ← תזכורות בוחרים שעה לכל מדד ולוחצים "הוסף תזכורות ליומן בטלפון".
  נוצר קובץ יומן עם אירוע יומי חוזר והתראה, שמוסיפים ליומן של הטלפון. זה עובד באייפון ובאנדרואיד
  גם כשהאפליקציה סגורה, בלי שרת ובלי תשלום.
  (התראות Push מהשרת היו דורשות את תוכנית Blaze בתשלום של Firebase.)

## איורי התרגילים

לכל 52 התרגילים במאגר יש איור מונפש (SVG) בתיקייה `public/exercises/`: דמות שמבצעת את התנועה מהתחלה לסוף בלולאה,
עם הציוד המתאים והשריר העובד מודגש בצבע של קבוצת השריר. הקבצים קטנים (כ-8KB כל אחד) ונשמרים מראש, אז הם עובדים גם בלי קליטה.

האיורים נוצרים מקוד: התנוחות מוגדרות ב-`scripts/poses.mjs` (זוויות מפרקים או יעד לכף היד/רגל), והמנוע ב-`scripts/figure.mjs`
מחשב את התנועה ומייצר אנימציה. הקבצים נוצרים אוטומטית בכל `npm run dev` ו-`npm run build` (גם ב-Vercel), ולכן לא צריך להעלות אותם ל-GitHub.
אפשר תמיד להחליף איור בתמונה, GIF או סרטון משלך מתוך כרטיס התרגיל.

## איך הפיצ׳רים עובדים

**משקל** — שקילה אחת לכל יום (הזנה חוזרת = עדכון). הממוצע השבועי מחושב לשבוע ראשון–שבת,
הממוצע החודשי לפי חודש קלנדרי, וההפרש מוצג מול השבוע/החודש הקודם.
**המגמה** מחושבת ברגרסיה ליניארית על השקילות ב-30/90 הימים האחרונים — כך יום "כבד" אחד לא מקפיץ את הקצב.
מוצג: קצב בק״ג לשבוע + שינוי כולל בתקופה. במסך ההגדרות בוחרים מטרה (חיטוב/מסה/שמירה) והצבעים מתאימים את עצמם.

**אימון פעיל** — הטיימר מבוסס על זמן ההתחלה, אז הוא ממשיך לרוץ גם אם סוגרים את האפליקציה.
לכל סט מוצג מה עשית בפעם הקודמת (עמודת "קודם"); אם משאירים שדה ריק ומסמנים ✓, הוא מתמלא מהפעם הקודמת.
סימון סט מפעיל טיימר מנוחה (ברירת מחדל 90 שנ׳, ניתן לשינוי בהגדרות, לכל תרגיל בתוכנית, או תוך כדי אימון) עם ±15 שנ׳ ודילוג.
בסיום: צליל + רטט. המסך נשאר דלוק במהלך האימון. רק סטים שסומנו נשמרים.

**שיאים** — ליד כל תרגיל מוצג השיא (המשקל הגבוה ביותר; בשוויון — יותר חזרות). סט ששובר שיא מקבל 🏆 כבר בזמן האימון,
ובסיכום מוצגת רשימת השיאים החדשים מול הקודמים.

> **מגבלה של iOS:** כשהאפליקציה ברקע/המסך כבוי, ספארי לא מנגן צליל ולא רוטט. הטיימר עצמו ממשיך נכון ויציג "המנוחה הסתיימה" כשחוזרים.

# מבנה הנתונים ב-Firestore

כל הנתונים של משתמש נמצאים תחת מסמך אחד: `users/{uid}`. אין שום נתון משותף בין משתמשים.

```
users/{uid}                                   ← פרופיל: email, createdAt, settings
├── weights/{YYYY-MM-DD}                      ← { date, kg, updatedAt }          שקילה אחת ליום
├── weeklyAverages/{YYYY-MM-DD של יום ראשון}  ← { weekStart, weekEnd, avg, count, min, max }
├── glucose/{readingId}                       ← { date, time, value (mg/dL), context, note }  כמה מדידות ביום
├── glucoseWeeklyAverages/{יום ראשון}         ← { weekStart, weekEnd, avg, count, min, max }
├── bloodPressure/{readingId}                 ← { date, time, sys, dia, pulse, note }
├── bloodPressureWeeklyAverages/{יום ראשון}   ← { weekStart, weekEnd, count, sysAvg, diaAvg, pulseAvg }
├── exercises/{exerciseId}                    ← { name, muscle, mediaUrl, mediaType, notes, builtin }
├── programs/{programId}                      ← { name, position, exercises: [{ uid, exerciseId, sets, reps, restSec }] }
├── sessions/{sessionId}                      ← { programId, programName, date, startedAt, endedAt, durationSec,
│                                                 exercises: [{ exerciseId, sets: [{ weight, reps }] }] }
└── personalRecords/{exerciseId}              ← { weight, reps, date, sessionId }
```

| אוסף | מתי נכתב | הערות |
|---|---|---|
| `weights` | בכל הזנה/עדכון/מחיקה של שקילה | מזהה המסמך הוא התאריך → הזנה חוזרת באותו יום מעדכנת |
| `weeklyAverages` | **אוטומטית** עם כל שינוי בשקילה | ממוצע לשבוע ראשון–שבת, נשמר במאגר |
| `glucose` | בכל הוספה/עריכה/מחיקה של מדידת סוכר | `context`: fasting (בצום), before (לפני ארוחה), after (אחרי ארוחה), bedtime (לפני שינה), other |
| `glucoseWeeklyAverages` | **אוטומטית** עם כל שינוי במדידות | ממוצע שבועי של כל המדידות בשבוע |
| `bloodPressure` | בכל הוספה/עריכה/מחיקה של מדידת לחץ דם | `pulse` אופציונלי |
| `bloodPressureWeeklyAverages` | **אוטומטית** עם כל שינוי | ממוצע שבועי לעליון, תחתון ודופק |
| `exercises` | רק תרגילים שיצרת או ערכת | 52 התרגילים המובנים הם חלק מהאפליקציה ולא נשמרים אם לא שונו |
| `programs` | ביצירה/עריכה של אימון | `position` = סדר הסבב (A→B→C→D) |
| `sessions` | בסיום כל אימון | רק סטים שסומנו כהושלמו. `programName` נשמר כדי שהיומן יציג אותו גם אם התוכנית נמחקה |
| `personalRecords` | **אוטומטית** אחרי כל אימון שנשמר/נמחק | שיא = המשקל הגבוה ביותר; בשוויון — יותר חזרות |

הממוצע החודשי והמגמה מחושבים באפליקציה מתוך `weights` (קוד ב-`src/lib/weightStats.js`).

### חוקי אבטחה (`firestore.rules`)

```
match /users/{userId}/{document=**} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
}
```

משתמש לא מחובר לא יכול לקרוא כלום, ומשתמש מחובר לא יכול לגשת לנתונים של משתמש אחר — גם אם ינסה ישירות מול ה-API.
